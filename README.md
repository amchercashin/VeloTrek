# Вёрсты

Веломаршруты по Москве и Подмосковью с картами, которые работают **без интернета**.

**[Открыть приложение](https://amchercashin.github.io/VeloTrek/)**

Идея простая: дома по Wi‑Fi выбираете маршрут и скачиваете карту, в дороге выключаете мобильный интернет (или его просто нет) — и едете по GPS. Телефон показывает, где вы, куда смотрите, на каком вы километре трека и не свернули ли не туда.

## Возможности

- **Каталог** — поиск, разделы, силуэт каждого маршрута, отметки «скачано»; режим «карта всех маршрутов»
- **Офлайн-карта** — коридор тайлов вдоль трека (масштабы 10–16) сохраняется в памяти телефона; размер и время скачивания видны заранее; загрузки идут очередью и не прерываются при переходе между экранами
- **Навигация без сети** — скорость, «км N из M», расстояние и стрелка до трека при сходе (с вибрацией), проехано и время в пути, компас; экран не гаснет
- **Надёжность** — сам маршрут тоже сохраняется на устройстве; при «лежащей» связи приложение не ждёт сеть; просит браузер не удалять карты
- **PWA** — ставится на экран «Домой», открывается без сети; светлая тема для солнца, тёмная и «ночная карта» для вечера

## Как это устроено

Чистый HTML/CSS/JS на ES-модулях, без сборки и npm-зависимостей в рантайме. Хостинг — GitHub Pages. Все библиотеки и шрифты лежат в репозитории, поэтому приложение не зависит от CDN и целиком работает офлайн.

| Что | Где |
|---|---|
| Точка входа, роутинг (`#/`, `#/map`, `#/r/<файл>`) | `js/main.js` |
| Экраны: каталог, маршрут, панели | `js/views/` |
| Каталог, загрузка KML/KMZ, офлайн-хранилище, тайлы, очередь скачиваний | `js/data/` |
| GPS, компас, положение относительно трека | `js/nav/navigator.js` |
| Карта (Leaflet 1.9, слой тайлов из IndexedDB) | `js/map/`, `vendor/leaflet/` |
| Геометрия, форматирование, распаковка KMZ без JSZip | `js/lib/` |
| Service Worker (оболочка cache-first, маршруты network-first с таймаутом) | `sw.js` |
| Генератор каталога `routes/index.json` | `scripts/generate-index.py` |

Хранилище — IndexedDB `velotrek-tiles`: тайлы, ссылки «тайл → маршруты» (общие тайлы не удаляются вместе с одним маршрутом), манифесты скачиваний и сами маршруты. Схема совместима с прежней версией приложения: уже скачанные карты сохраняются.

> **Тайлы.** Сейчас используется `tile.openstreetmap.org`. [Политика OSM](https://operations.osmfoundation.org/policies/tiles/) не рассчитана на массовое скачивание для офлайна, поэтому при росте аудитории стоит перейти на провайдера, который это разрешает (например, свой сервер тайлов или коммерческий с ключом). Источник задаётся в одном месте — `TILE_SOURCE` в `js/data/tiles.js`.

## Добавление маршрута

Чтобы добавить новый маршрут:

### 1. Подготовьте файл

Файл маршрута в формате **KML** или **KMZ** (Google Earth, Locus Map, OsmAnd и др.).

**Требования к файлу:**
- Формат: `.kml` или `.kmz`
- Должен содержать хотя бы один `LineString` (трек маршрута)
- Точки интереса (`Point`) — опционально, но полезно (привалы, магазины, достопримечательности)
- Имя файла: латиница, через дефисы, без пробелов. Например: `moscow-river-zvenigorod.kml`

**Описание маршрута** добавляется внутри KML в теге `<description>` элемента `<Document>`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<kml xmlns="http://www.opengis.net/kml/2.2">
  <Document>
    <name>Москва-река (Дорохово — Звенигород)</name>
    <description>
      Живописный маршрут вдоль Москвы-реки.
      Подробнее: https://example.com/route
    </description>
    <!-- Placemarks с LineString и Point -->
  </Document>
</kml>
```

Приложение автоматически извлечёт из файла:
- Название маршрута (`<name>`)
- Описание (`<description>`)
- Длину трека и размах (вычисляются из координат). Самый длинный трек в файле считается основным, остальные показываются пунктиром как варианты и подъезды
- Высоты, подъём, спуск — вычисляются из координат треков (3-я составляющая каждой точки KML). Скользящее среднее по 5 точкам сглаживает шум SRTM-данных
- Точки интереса (POI)

### 2. Добавьте файл в репозиторий

**Вариант A — через веб-интерфейс GitHub (просто):**

1. Откройте папку [`routes/`](https://github.com/amchercashin/VeloTrek/tree/main/routes) в этом репозитории
2. Нажмите **Add file → Upload files**
3. Перетащите ваш KML/KMZ файл
4. Нажмите **Commit changes** (или **Propose changes** если у вас нет прав записи — создастся Pull Request)

**Вариант B — через git (для разработчиков):**

```bash
cp your-route.kml routes/
git add routes/your-route.kml
git commit -m "feat: добавить маршрут Название"
git push
```

### 3. Готово

После коммита GitHub Action автоматически:
- Распарсит ваш KML-файл
- Извлечёт название, статистику, координаты
- Обновит `routes/index.json`
- Маршрут появится в приложении (с силуэтом в каталоге и на карте всех маршрутов)

## Локальная разработка

```bash
git clone https://github.com/amchercashin/VeloTrek.git
cd VeloTrek
npx http-server -p 8080 -c-1 .     # или python3 -m http.server 8080
# открыть http://localhost:8080
```

Проверки:

```bash
npm test                             # юнит-тесты (node --test), запускаются и в CI
python3 scripts/generate-index.py    # пересобрать каталог после изменения маршрутов

npm install                          # Playwright — только для сквозного теста
E2E_STUB_TILES=1 npm run e2e         # каталог → скачать → без сети → навигация по GPS
```

При изменении файлов оболочки (CSS/JS/HTML/шрифты) GitHub Action поднимает `SHELL_VERSION` в `sw.js`, и установленные приложения предлагают обновиться. Новые JS-модули нужно добавить в `SHELL_FILES` в `sw.js` — за этим следит юнит-тест.
